# Loom Bulk — Behavioral Specification

> Command: `loom bulk <module> [flags]`

`loom bulk` scaffolds a bulk wrapper module from an existing module's config. It introspects the child module's declared parameters and emits a `loom.jsonnet` whose `spec.modules` entries are generated from an `items` list — one entry per execution of the child module.

## Inputs

| Input | Description |
|-------|-------------|
| `<module>` | Required. Path or git URL of the child module (same source forms as `loom run`). |
| `-o, --output` | Output directory for the generated wrapper. Defaults to `.`. |
| `-n, --name` | Wrapper module name. Defaults to `bulk-<childModuleName>`. |
| `--items` | Optional. YAML file containing a list of `map[string]string` param sets to seed the `items` list. |
| `--name-param` | Optional. Child param whose value becomes the child entry name suffix. Defaults to the item index. |

## Behaviors

### B1: Child param introspection

The child module's config is loaded (`loom.yaml` or `loom.jsonnet`) and validated. Each placeholder item in the generated wrapper contains one field per declared **static** param:

| Param definition | Placeholder value | Annotation |
|---|---|---|
| `required: true` | `'CHANGEME'` | `// required` comment |
| has `default` | the default value | none |
| neither | `''` | none |

Dynamic params are **not** included — they resolve inside the child at run time.

### B2: Items from file

With `--items <file.yaml>`, the file must contain a YAML list of `map[string]string`. Each map becomes one item, replacing the placeholder. Validation before emission:

- Every key must be a declared param (static or dynamic) of the child — mirrors run-time P3.
- Every `required` static param without a default must be present in every item.

### B3: Generated wrapper structure

```jsonnet
// Generated by loom bulk from <module>.
local items = [
  {
    serviceName: 'CHANGEME',  // required
    namespace: 'default',
  },
];

{
  apiVersion: 'loom.rickliujh.github.io/v1beta1',
  kind: 'Loom',
  metadata: { name: '<wrapperName>' },
  spec: {
    modules: [
      {
        name: '<childName>-' + std.toString(i),
        source: '<source>',
        params: items[i],
      }
      for i in std.range(0, std.length(items) - 1)
    ],
  },
}
```

With `--name-param serviceName`, the entry name becomes `'<childName>-' + items[i].serviceName`.

### B4: Source path derivation

| `<module>` argument | Emitted `source` |
|---|---|
| Local path | Path relative to the output directory (absolute if no relative path exists) |
| Git URL (with optional `//subdir`) | The URL verbatim |

### B5: Jsonnet identifier quoting

Param names that are not valid Jsonnet identifiers (`[A-Za-z_][A-Za-z0-9_]*`) are emitted as quoted fields (`'my-param': ...`) and accessed with index syntax (`items[i]['my-param']`).

### B6: No overwrite

If `<output>/loom.jsonnet` or `<output>/loom.yaml` already exists, the command fails — a directory must not end up with two config files, and existing work is never clobbered.

### B7: Self-verification

After writing, the generated wrapper is loaded back through the standard config loader (Jsonnet evaluation + validation). Emission of an invalid wrapper is a command failure.

### B8: Target topology note

If the child module declares `spec.target`, each generated entry runs with its own clone/branch/PR (one PR per item). The generated file includes a comment stating this and pointing to the single-batch-PR alternative (wrapper-owned target with a target-less child). `loom bulk` never rewrites the child module.

## Error Conditions

| Condition | Error |
|-----------|-------|
| Child module cannot be loaded/validated | propagated load/validate error |
| Output config already exists | `refusing to overwrite existing <file>` |
| `--items` file unreadable or not a list of string maps | `reading items file: ...` / `parsing items file: ...` |
| Item key not declared in child | `item <N>: undeclared parameter "<name>"` |
| Item missing a required param (no default) | `item <N>: required parameter "<name>" not provided` |
| `--name-param` not a declared param | `--name-param "<name>" is not a declared parameter` |
| Generated wrapper fails to load back | `generated wrapper failed validation: ...` |
